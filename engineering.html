Engineering Lab

How a personally meaningful typing challenge became an educational prototype that visitors can explore and measure.

Open the Typing Setup Lab

Problem definition

Typing a short message can require reaching, targeting individual keys, and correcting unintended input. Those demands can make everyday communication more effortful for some people with one-sided motor difficulties.

User needs

The design brief considers choice of input, room to rest, minimal equipment cost, clear controls, and private reflection. These priorities come from lived experience and need review with intended users.

Design requirements

  • Use one fixed message and one clearly described setup change per comparison.
  • Support keyboard and on-screen input, either setup order, repeated trials, and rest without a deadline.
  • Report time, final text errors, and editing actions separately. Let visitors add comfort and preference.
  • Keep results in the session unless the visitor exports them or saves to the browser-local journal.

Demonstrated prototypes

The Typing Setup Lab implements the comparison in a browser. Its illustrated keyguard shows how openings line up with keys. The 3D Anatomy Studio and the balance model demonstrate related concepts using simplified models with text or static alternatives.

Testing methodology

  1. Select a change and use the same device, input method, and sample for both setups.
  2. Start a trial, type the sample, and finish. Elapsed time excludes explicit pauses and includes operating the controls.
  3. Review the character edit distance and observed correction actions. Optionally rate comfort and choose a preference.
  4. Repeat in the other order if comfortable. Look for trade-offs across trials and record relevant context.

Results

The public lab begins with an empty results view. It reports measurements from trials you finish in your browser. The project has no participant dataset or aggregate performance findings. See the repository documentation for software verification.

Limitations

Erry Mobility is an educational assistive technology project. It has no established clinical effectiveness and provides no diagnosis, personalised rehabilitation, or substitute for occupational therapy or professional assessment. It is an educational web prototype and has not been developed as a medical device. Personal experience informed the design and represents one perspective.

Device differences, fatigue, practice, familiarity, and trial order can affect results. Browser editing events cannot identify every corrected error or distinguish an intentional edit from an accidental key press. A single English sample covers a narrow task. Suitability and usability need further evaluation with intended users.

Planned experiments and future ideas

A proposed usability evaluation could ask whether users can select a setup, complete a trial, and interpret the results independently. With appropriate oversight and accessible consent, a later study could compare repeated trials in both orders, allowing rest and documenting the equipment and chosen changes. Future work could explore affordable keyguard designs and additional input methods.
